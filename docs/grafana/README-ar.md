# لوحة معلومات Grafana

`rospanel.json` لوحة معلومات جاهزة لمقاييس اللوحة نفسها: المستخدمون، وحركة المرور والإنتاجية، وصف واحد لكل خادم في الأسطول، وجهاز اللوحة نفسه. استوردها في Grafana تحت **Dashboards → New → Import**، وارفع الملف، واختر مصدر بيانات Prometheus حين يسأل.

## توجيه Prometheus إلى اللوحة

نقطة نهاية المقاييس هي `GET https://<panel>/<api-path>/v1/metrics`. وهي خلف مفتاح API نفسه الذي يحمي بقية واجهة API الخارجية، فيجب أن يحمله الكشط. أنشئ مفتاحا تحت **Settings → API**، ثم:

```yaml
scrape_configs:
  - job_name: rospanel
    scheme: https
    metrics_path: /<api-path>/v1/metrics
    authorization:
      credentials: rp_your_api_key_here
    static_configs:
      - targets: ['panel.example.com']
```

**المفتاح ليس للقراءة فقط.** لا توجد في اللوحة مفاتيح API للقراءة فقط: فأي مفتاح صالح يفتح واجهة `/v1` كلها، بما في ذلك إنشاء المستخدمين والخوادم وحذفهم. وملف `prometheus.yml` كثيرا ما يكون مقروءا للجميع ومودعا في مستودع تهيئة، فتعامل مع المفتاح فيه بوصفه اعتماد لوحة فعلا — احصر الوصول إلى الملف، وأبعده عن التحكم بالإصدار، وأعط الكشط مفتاحا خاصا به كي يمكن إلغاؤه وحده.

## ما تتوقعه اللوحات

كل شيء يكشط من هدف واحد، فلا يوجد ترشيح مدمج لـ `instance` أو `job`. وأمران يجدر معرفتهما حين تبدو لوحة فارغة لا خاطئة:

- **CPU والذاكرة والقرص لكل خادم** لا يبلغ عنها إلا عقدة سجل وكيلها حضوره. فالخادم الذي أضفته ولم تثبته قط ليست له إحصاءات جهاز إطلاقا، ويسقط من تلك اللوحات الثلاث بدلا من إظهار صفر.
- **الأجهزة المرتبطة** لا تصدر إلا ما دام ربط الأجهزة (HWID) مشغلا.

لوحات حركة المرور تعود إلى الصفر عند منتصف الليل المحلي في المنطقة الزمنية للمشغل، لا على 24 ساعة متدحرجة — وهذا ما تحسبه اللوحة نفسها، فتتبعه لوحة المعلومات بدلا من اختراع تعريف ثان.
