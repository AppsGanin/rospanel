# Дашборд Grafana

`rospanel.json` — готовый дашборд по собственным метрикам панели: пользователи,
трафик и пропускная способность, строка на каждый сервер парка и сам хост панели.
Импортируйте его в Grafana через **Dashboards → New → Import**, загрузите файл и
выберите свой источник данных Prometheus, когда его спросят.

## Как направить Prometheus на панель

Эндпоинт метрик — `GET https://<panel>/<api-path>/v1/metrics`. Он закрыт тем же
ключом API, что и остальной внешний API, поэтому сбор должен его нести. Создайте
ключ в **Настройки → API**, затем:

```yaml
scrape_configs:
  - job_name: rospanel
    scheme: https
    metrics_path: /<api-path>/v1/metrics
    authorization:
      credentials: rp_your_api_key_here
    static_configs:
      - targets: ['panel.example.com']
```

**Ключ не только для чтения.** В панели нет ключей API только для чтения: любой
действующий ключ открывает всю поверхность `/v1`, включая создание и удаление
пользователей и серверов. `prometheus.yml` — файл, который часто доступен на
чтение всем и попадает в репозиторий конфигурации, поэтому относитесь к ключу в нём
как к учётным данным панели: ограничьте доступ к файлу, держите его вне системы
контроля версий и выдайте сбору отдельный ключ, чтобы его можно было отозвать
отдельно.

## Чего ждут панели

Всё собирается с одной цели, поэтому фильтрации по `instance` или `job` внутри
нет. Две вещи стоит знать, когда панель выглядит пустой, а не неверной:

- **CPU, память и диск по серверам** сообщает только нода, чей агент отметился.
  У сервера, который добавили, но так и не установили, статистики хоста нет вовсе,
  и он выпадает из этих трёх панелей, а не показывает ноль.
- **Привязанные устройства** выдаются, только пока включена привязка устройств
  (HWID).

Панели трафика сбрасываются в местную полночь в часовом поясе оператора, а не по
скользящим 24 часам: так считает сама панель, поэтому дашборд следует за ней, а не
изобретает второе определение.
