# داشبورد Grafana

`rospanel.json` یک داشبورد آماده برای متریک‌های خود پنل است: کاربران، ترافیک و
توان عبوری، یک ردیف برای هر سرور در ناوگان، و خود میزبان پنل. آن را در Grafana از
مسیر **Dashboards → New → Import** وارد کنید، فایل را بارگذاری کنید و هنگام درخواست،
منبع دادهٔ Prometheus خود را انتخاب کنید.

## اتصال Prometheus به پنل

نقطهٔ پایانی متریک‌ها `GET https://<panel>/<api-path>/v1/metrics` است. پشت همان کلید API
قرار دارد که بقیهٔ API خارجی، پس scrape باید کلید را همراه داشته باشد. یک کلید در
**Settings → API** بسازید، سپس:

```yaml
scrape_configs:
  - job_name: rospanel
    scheme: https
    metrics_path: /<api-path>/v1/metrics
    authorization:
      credentials: rp_your_api_key_here
    static_configs:
      - targets: ['panel.example.com']
```

**کلید فقط‌خواندنی نیست.** پنل کلید API فقط‌خواندنی ندارد: هر کلید معتبر کل سطح `/v1`
را باز می‌کند، از جمله ساخت و حذف کاربران و سرورها. فایل `prometheus.yml` معمولاً
برای همه قابل خواندن است و در مخزن پیکربندی commit می‌شود، پس کلید داخل آن را
اعتبارنامهٔ پنل بدانید: دسترسی فایل را محدود کنید، آن را از کنترل نسخه بیرون نگه دارید
و برای scrape کلید جداگانه بسازید تا بتوانید مستقل از بقیه باطلش کنید.

## پنل‌ها چه انتظاری دارند

همه‌چیز از یک هدف scrape می‌شود، بنابراین فیلتر `instance` یا `job` از پیش تعبیه نشده است.
دو نکته وقتی یک پنل خالی است و نه اشتباه:

- **CPU، حافظه و دیسک هر سرور** فقط توسط نودی گزارش می‌شود که عاملش check-in کرده باشد.
  سروری که اضافه شده ولی هرگز نصب نشده هیچ آمار میزبانی ندارد و از این سه پنل بیرون
  می‌افتد، نه اینکه صفر نشان دهد.
- **دستگاه‌های متصل** فقط وقتی منتشر می‌شود که اتصال دستگاه (HWID) روشن باشد.

پنل‌های ترافیک در نیمه‌شب محلی به وقت اپراتور صفر می‌شوند، نه در یک بازهٔ ۲۴ ساعتهٔ
غلتان — این همان چیزی است که خود پنل می‌شمارد، پس داشبورد از آن پیروی می‌کند نه اینکه
تعریف دومی بسازد.
