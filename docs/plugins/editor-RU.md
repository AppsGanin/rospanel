# Редактор плагинов в панели

[English](editor.md)

Плагин можно написать прямо в панели: **Настройки → Плагины → Редактор плагинов → Новый плагин**.
Там же тесты, пробный запуск, установка и скачивание. Пока черновик не установлен, он ничего не
меняет в панели. Редактор доступен с правом `plugins.manage`.

## Три способа начать

| | Что получится |
|---|---|
| **Конструктор правил** | «Когда событие → если условие → сделать действие», без кода. Панель собирает из правил обычный плагин. |
| **Код** | Шаблон `plugin new`: `main.js`, `plugin.json`, миграция, `test.js`, переводы. |
| **Из .zip** | Пакет плагина или исходники, скачанные из редактора. |

Установленный плагин открывается кнопкой **Открыть в редакторе** на его карточке: получится
черновик с его кодом, который ставится обновлением.

## Конструктор правил

Правило — это:

- **Когда:** событие панели (те же, что у вебхуков) или расписание.
- **Если:** условия на поля события — `равно`, `не равно`, `содержит`, `больше`, `меньше`,
  `пусто`, `не пусто`; все сразу или любое.
- **То:** одно или несколько действий:

| Действие | Что делает |
|---|---|
| Написать в Telegram | `sendMessage` в чат; токен бота — в настройках плагина. Чат `{{user.telegram_id}}` — сам пользователь. |
| Написать в Discord | В вебхук из настроек плагина. |
| HTTP-запрос | На ваш адрес; без тела отправится всё событие JSON. Заголовок `Authorization` — из настроек. |
| Продлить подписку | На N дней. |
| Включить / отключить пользователя | |
| Добавить / снять тег | |
| Записать в лог плагина | |

В текстах, чате, адресе и теле запроса работают подстановки: `{{user.name}}`, `{{user.id}}`,
`{{user.telegram_id}}`, `{{data.<поле>}}` — любое поле события, `{{event}}`, `{{now}}`.
В адресе подставляется только путь и query: хост фиксирован, его оператор видит при установке.

Права и сеть плагин получает ровно под правила: события дают `users.view` (денежные — ещё
`billing.view`), действия с пользователем — `users.manage`; хосты — `api.telegram.org`,
`discord.com` и хосты ваших HTTP-запросов.

Каждое действие выполняется для события один раз: если доставка повторится после сбоя, уже
сделанные действия не повторятся. Правило по расписанию не может менять пользователя — у него
нет пользователя.

Вкладка **Код** показывает собранный `main.js`: правила лежат в нём как JSON, ниже — код, который
их выполняет. **Править код вручную** переводит черновик на код насовсем — правила остаются в
`main.js`, конструктор для этого черновика закрывается.

## Код

Слева файлы, справа редактор: подсветка, `Tab`, поиск (`Ctrl/⌘+F`), подсказки `panel.*`.
Всё сохраняется само. Файлы, которые не входят в пакет (`test.js`, `dev.config.json`,
`rospanel.d.ts`), остаются в черновике и в скачанных исходниках.

## Тесты

**Запустить тесты** выполняет `test.js` в песочнице панели — как `rospanel plugin test`:
интернет и `panel.api` подменены (`mock.http`, `mock.api`), настройки берутся из
`dev.config.json`. Что тесты не проверяют — в [тестах и отладке](testing-RU.md).

## Пробный запуск

Одно событие в `onEvent` с вашими данными или вызов любой экспортированной функции с аргументом.
Видно результат, лог и все запросы плагина.

По умолчанию запросы не уходят: интернет отвечает «нет мока», `panel.api` — подсказкой. Две
галочки это меняют:

- **Настоящие запросы в интернет** — только к хостам из `net`, через тот же защищённый fetch,
  что у установленного плагина. Сообщения и вебхуки уйдут по-настоящему.
- **Читать данные панели** — `panel.api` только `GET`, с правами, которые есть и у плагина, и
  у вас.

Песочница одна на панель: второй запуск ждёт несколько секунд или отвечает «песочница занята».
Тесты ограничены 60 секундами, пробный запуск — 30.

## Установка и скачивание

- **Проверить** — пакет так, как его прочитает установка: права, сеть, функции, размер или
  список ошибок.
- **Установить** — обычный экран согласия с паролем; плагин с тем же ID обновляется (со снимком
  базы и откатом).
- **Скачать** — пакет для установки на другой панели или исходники с тестами, чтобы продолжить в
  своём редакторе с `rospanel plugin test | dev | pack`. Исходники снова открываются в
  панели через **Из .zip**; черновик конструктора остаётся конструктором (правила лежат в
  `rules.json`).

Черновики хранятся в базе панели зашифрованными, как настройки плагинов.
